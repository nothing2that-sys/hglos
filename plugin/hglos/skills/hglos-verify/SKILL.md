# HGLOS Verify - 검증 레그

공통 진입을 먼저 읽는다: 원본 `../../ENTRY.md`, 설치본 `ENTRY.md`. 필수 공통 규칙을 생략하지 않는다.

먼저 호스트 실행 규칙을 읽는다: 설치본은 스킬 루트의 `HOST.md`, plugin 배치는 `../../HOST.md`.

검증 실행 경로는 세 가지이고 용도가 다르다. ReviewGate 경로는 그 옆에 함께 쓰는 선택 경로다.

| 경로 | 문서 | 용도 |
|---|---|---|
| 교차 회사 실행기 | `agents/cross-host-validator.md` (`scripts/cross_host.py`) | 모드 A 적대 검토와 긴 맥락 읽기·확인. 메인이 명령 하나로 다른 회사 CLI(`codex exec`, `claude -p`, `agy -p`)를 읽기 전용으로 부르고 결과를 파일로 받는다. 다른 회사 모델을 쓰는 1차 경로다 |
| 기준 경로 | `agents/validator.md` | 모드 A의 교차 검증 1회와 실행기 실패 시 우회. `cross_host.py`를 부르지 않는다 |
| 네이티브·모드 B | `agents/native-validator.md` 또는 사람이 시작한 다른 회사 새 세션 | 새 맥락 네이티브 검증자(모드 A·B), 모드 B 종결 검증. 실행기는 모드 B를 하지 않는다 |
| ReviewGate 병행 경로(선택) | `agents/reviewgate-validator.md` (`scripts/reviewgate_bridge.py`) | `REVIEWGATE_CLI`가 있을 때 외부 프로그램 ReviewGate로 다른 회사 CLI·API 모델의 모드 A 검수를 받는다. 정식 회차는 검수자 1개를 전체 모델 ID로 지정한 code 프로필 review이면서 모든 attempt의 관측 모델이 확인된 경우뿐이고, 나머지는 참고 검수다. 모드 B는 하지 않는다 |

새 세션용 전달문은 위 경로를 모두 쓸 수 없을 때의 최후 강등 경로다.

## 역할

너는 **오케스트레이터**다. 리뷰하지 않는다.

리뷰는 **이전 대화를 상속하지 않은 새 검증자**가 한다. 호스트의 네이티브 에이전트나 외부 CLI를 선택한다.
Codex를 사용했다는 이유만으로 구현자와 다른 회사 모델이라고 기록하지 않는다.
너의 일은 회차 관리, 지문 비교, 정지 판정, 보고다.

**직접 리뷰하지 않는다.** 이 구조의 가치는 만든 쪽과 맥락을 공유하지 않는 판단을 가져오는 것이다.
네 리뷰를 섞으면 출처가 오염된다. 포워딩한 발견에 네 분석을 덧붙이지도 않는다
(실측: 덧붙인 한 마디가 도구의 유일한 미검출을 가렸다).

## 검증자 독립성과 기록

**맥락 분리는 필수다.** 검증자는 구현 세션과 맥락을 공유하지 않는 새 서브에이전트 또는 새 세션이다.
그 위에서 검증자를 다음 순서로 고른다. 위 순위를 쓸 수 없으면 사람에게 묻지 않고 다음 순위로 내려가고, 어느 순위였는지 기록한다.

| 순위 | 검증자 | 기록 |
|---|---|---|
| 1 | 구현자와 다른 회사의 모델 (실제 선택한 모델로 확인) | 같은 패밀리: 아니오 |
| 2 | 같은 회사의 **다른 모델**, 구현자와 비슷한 등급 (구현자보다 한 단계 이상 작은 모델 제외) | 같은 패밀리: 예 · 다른 모델 |
| 3 | 구현자와 같은 모델 | 같은 패밀리: 예 · 같은 모델 |
| 금지 | 오케스트레이터 자신, 또는 구현한 세션 | - |

2순위에서 구현자보다 확연히 작은 모델로 내리지 않는다 - 다양성은 생겨도 깊은 결함을 놓친다.
같은 회사 모델은 맹점을 공유할 수 있으므로 1순위가 우선이다. 순위별 신규 발견 수를 쌓아 이 순서를 실측으로 다시 본다.

**보고서 머리에 반드시 적는다**:

```
검증자: <모델/도구 이름과 버전> · 요청 모델 <ID> · 관측 모델 <ID>(<출처 파일:행 필드>) · 판정: <일치|불일치|로그 없음|최종 작성자 미확인> · 순위: <1|2|3|미확인(<판정> · 요청 기준 n)> · 세션: 새 세션/새 서브에이전트 · 구현자와 같은 패밀리: 예/아니오
```

이 줄이 없는 보고는 미완성이다. **모델 이름은 검증자 자신의 출력**(CLI 버전 출력, CLI가 남긴 로컬 기록, 서브에이전트의 자기 보고)에서 옮긴다 -
오케스트레이터가 추정해 채우지 않는다. 요청 모델은 호출 인자, 관측 모델은 그 출력·기록에서 기계적으로 읽은 값이다.
**실행기 경로**(`agents/cross-host-validator.md`)에서는 순위를 판정이 `일치`일 때만 관측 모델로 매긴다. `일치`가 아니거나,
순위표에서 제외된 모델이거나, run 1회차와 모델이 다르면 정식 회차가 아니다: `round_N.json`을 만들지 않고 회차 상한·수렴 비교·
순위 집계에서 뺀다. 실행기 경로는 `call_<N>.json`의 `header`를 그대로 옮긴다.
**ReviewGate 경로**(`agents/reviewgate-validator.md`)도 같은 판정을 ReviewGate가 돌려준 attempt마다 적용하고, 모든 attempt가 `일치`여야
회차가 `일치`다. 정식 여부는 `call_<N>.json`의 `formal_round`·`formal_reasons`이고, 머리줄은 그 `header`를 그대로 옮긴다.
참고 검수의 지적은 MAIN이 원문을 직접 확인한 뒤에만 발견으로 채택한다. ReviewGate 참고 검수만으로 자기 구현을 정식 판정하지 않는다.
**기준 경로(`agents/validator.md`)와 네이티브 검증자**는 이 신원 조건을 쓰지 않는다. 기준 경로는 `--ephemeral`·모델 미지정이라
CLI 로컬 기록으로 관측할 수 없으므로, 기존 규칙대로 검증자 자신의 출력(CLI 버전 출력, 호스트 메타데이터, 자기 보고)으로 적고
확인할 수 없는 칸은 `미확인`으로 둔다. 그 회차의 정식 여부는 기존 계약 검사(`validate_findings.py`·`contract_violations`)로 정한다. 2·3순위로 내렸으면 위 순위를 못 쓴 이유를 **오류 원문**과 함께 적는다.
도구가 없다는 capability 확인도 근거가 된다. 실행하지 않은 도구의 오류를 지어내지 않는다.
이유 없이 3순위로 내려간 보고는 미완성이다.
**판정 보고 원문은 파일로 남긴다** (모드 B 는 `<산출 폴더>/verdict.md`). 대화에만 두면 세션과 함께 사라진다.

## 선행 조건

- 네이티브 새 검증자 또는 독립 CLI를 쓸 수 있는가. 둘 다 없으면 새 세션 전달문을 만들고 독립 검증은 미검증으로 남긴다.
- 모드 A: 리뷰할 변경분이 있는가 (`git status`, `git diff --stat`, 미추적 파일 목록). 없으면 멈춘다.
  모드 B: 커밋 후에도 계획서와 결과물을 검증할 수 있다. 변경분 부재만으로 거절하지 않는다.
- **출력 위치는 실행마다 새로 만든다**: `<repo>/validation/<run-id>/`. 이미 있는(특히 커밋된) 회차 폴더에 다시 쓰지 않는다.
  커밋된 결과를 덮으면 `git diff` 가 오염된다.
- 같은 run의 대상 파일·내용과 검증자 모델/도구를 고정한다. 모델/범위/작업트리가 달라지면 새 run으로 시작한다.
  `guard_integrity.py`에 더해 미추적 파일이 범위에 있으면 그 내용 해시도 전후 대조한다.

## 모드 A - 변경분 적대적 검증 (고정점)

### 회차 프로토콜

**1회차**: 선택한 실행 경로의 agent 지침을 읽고 새 검증자를 띄운다. 넘길 것 - `repo_path`, `scope`(기본 uncommitted 전체),
`round`, `output_dir`(위 run 폴더), `skill_root`.
검증 원문을 변환해 `round_N.md`(전문)와 `round_N.json`(요약)을 남긴다.
보조 에이전트가 읽기 전용이면 오케스트레이터가 저장·변환하고 판정 스크립트 출력만 사용한다.

**반환 요약 외에 아무것도 컨텍스트로 가져오지 않는다.** `round_N.md` 와 검증자 원문을 열지 않는다.

**2회차 이후**: **반드시 새 서브에이전트.** 이어 시키지 않는다. 이전 회차 발견을 검증자에게 알려주지 않는다.
회차 간 독립이 고정점 판정의 전제다.

### 정지 판정 - 스크립트로

```bash
python "<이 스킬>/scripts/compare_rounds.py" "<run 폴더>" --cap 3
```

- `계속 - N회 남음` → 새 서브에이전트로 다음 회차
- `수렴 정지` / `효용 정지` / `예산 정지` → 멈추고 보고
- `판정불가` → 검증자 호출 실패. 재실행 전 환경 확인

실패 회차는 상한에 들어가지 않는다. 상한 안에서는 회차 진행 여부를 사람에게 묻지 않는다.

**상한 3은 확정값이다** - 20행·591행·1289행 diff 세 대상에서 모두 3회차에 수렴했다.

### 상한을 다 쓰고도 수렴하지 않으면

검증을 반복하지 않는다. 보고에 "예산 정지 - 잔존 리스크 미지수"를 적고, **설계로 되돌릴지** 사람에게 묻는다.
같은 변경분에 상한을 올려 다시 돌리는 것은 표적 이동을 수렴으로 오독하는 길이다.

### 최종 보고

`round_*.json` 의 `claim` 필드로 구성한다.

```markdown
# 적대적 검증 결과 - <대상>
검증자: <모델/버전> · 요청 모델 <ID> · 관측 모델 <ID>(<출처>) · 판정: <일치|…> · 순위: <1|2|3> · 세션: 새 세션/새 서브에이전트 · 구현자와 같은 패밀리: 예/아니오

## 정지 조건: <수렴 / 효용 / 예산>
- 실행 회차: <성공 n> (실패 <m>) / 상한 3
- 총 고유 지문: <n> · 회차별 신규: R1 <n> / R2 <n> / R3 <n>

## 잔존 리스크
<수렴·효용: "버그 없음"이 아니라 "이 예산에서 더 안 나온다". 예산: 잔존 리스크 미지수, 설계 되돌림 검토>

## 발견 (심각도 순, 회차 통합)
## 처리 대기 - 어느 항목을 고칠지 선택 요청
```

수렴 정지와 예산 정지는 의미가 다르다. 후자를 전자처럼 쓰면 없는 안전감을 만든다.

## 모드 B - slice 종결 검증

구현 레그가 "종결 조건을 다 채웠다"고 보고했을 때 쓴다. **계획서의 종결 조건을 직접 재현**하고 판정한다.
구현자의 보고를 근거로 쓰지 않는다.

보고서 절 (순서 유지):

0. **검증 단계 판정표** - 정본이나 계획서가 검증 단계를 정했으면 단계별 판정과 직접 확인한 근거. 없으면 "정해진 단계 없음"
1. **종결 조건 재현표** - 조건 / 판정 수단 / 원문 출처 / 결과 / 판정 / 구현자 판정과 일치 여부
2. **실행 원문** - 조건별 명령과 출력 그대로. 요약하지 않는다
3. **중점 확인** - 계획서가 지목한 항목. 그리고 **오라클 무결성**: `git diff --stat <되돌림 지점> -- <oracle 경로>` 가
   비어 있어야 한다. 오라클 경로가 바뀌었으면 그 경로로 얻은 초록은 전부 무효로 적는다
   해시 목록(MANIFEST 등)으로 무결성을 보는 경우, 검사 스크립트가 **변조 사본에서 0 이 아닌 종료 코드를 내는지 먼저 실측**하고
   그 로그를 남긴다. 실행 셸을 가정하지 않는다(Windows pwsh 에는 `bash`·`sha256sum` 이 없다). 전·후 검사가 실제로 실행된 기록이
   없으면 "미검증"이다 - exit 0 로그만으로 통과라고 쓰지 않는다
4. **발견 4분류**
   | 분류 | 의미 |
   |---|---|
   | 미달 | 종결을 뒤집는다. **이것만 정지 사유** |
   | 구현자 주장과 어긋남 | 조건은 성립하나 보고가 틀림. 신뢰도 정보 |
   | 정본과 어긋남 | 정본 결함인지 구현 이탈인지 구분해 적는다 |
   | 재현 못 함 | 검증의 공백. 없으면 "전부 확인했다"로 읽힌다 |
5. **제한 및 위험** - 이번 판정이 무엇에 한정되는지, 어떤 환경에서 돌렸는지
6. **판정** - 통과 / 미달 / 조건부(조건 열거) + **근거**(어느 절의 어느 행) + **범위 한정문**: 이 판정이 승인하지 **않는** 것을 적는다

**개수·집합 주장은 스크립트 출력으로만 판정한다.** 사람이나 모델이 센 숫자는 근거가 아니다.
개수가 아니라 이름을 양방향 차집합으로 대조한다:

```bash
python <이 스킬>/scripts/set_diff.py <기대 목록> <실제 목록>
```

**병렬로 구현된 slice 는 합친 결과에 대해 한 번 더** 모드 B 를 돌린다. 작업별 통과는 통합 통과가 아니다.

## 절대 금지

- **수정 자동 적용.** 발견을 제시하고 멈춘다. 고칠 항목은 사람이 고른다.
- **정지를 승인으로 바꾸기.** 이 루프는 "다 됐다"고 주장하지 않는다. 종결 승인은 사람이 한다.
- **검증자 실패를 자기 리뷰로 대체.**
- **실패를 조용히 넘기기.** 실패 회차가 있으면 보고에 적는다. 3회 중 2회 성공이면 "3회 실행"이라 쓰지 않는다.
- **검증자 기록 줄 생략.**

## 관측 결과 (누적)

## 도구 프로파일

- **잡는다**: 널 역참조, 0 나눗셈, 값/참조 혼동으로 인한 조용한 쓰기 유실, 검증 축 오류. 컴파일되고 크래시도 안 나는 조용한 실패
- **놓친다**: 조기 반환 경로의 리소스 누수(특히 신규 함수). 이 도구를 돌렸다고 리소스 관리 검증이 끝난 것이 아니다
