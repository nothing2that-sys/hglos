# 계획서 항목 정의와 판정 규칙

계획서를 쓰기 전에 읽는다. 기억으로 채우지 않는다.

## 필수 항목 8

| # | 항목 | 비어 있으면 |
|---|---|---|
| 1 | 닫는 운영 주장 | "없음 - 기반 작업" 명시. 기반 작업이 3회 연속이면 사람에게 알린다 |
| 2 | 종결 조건 + 판정 수단 + 미달 예시 | 계획 아님 |
| 3 | 하지 않을 것 | 계획 아님 |
| 4 | 보존 범위 (관측자별) | 동작 보존을 주장할 수 없다 |
| 5 | 사라지는 것 | 없어질 코드를 고치는 낭비를 막을 수 없다 |
| 6 | 검증 가능 전제 | 설계가 사실 위에 서지 않는다 |
| 7 | 미결 + 닫히는 조건 + 필요 시점 + 누가 | 영구 대기 항목이 생긴다 |
| 8 | 되돌림 지점 | 착수 불가 |

값이 없으면 "없음"을 적는다. 빈 칸은 "안 봤다"와 구분되지 않는다.

## 검증 가능 전제 규칙 4

1. 결과 칸이 빈 전제가 하나라도 있으면 게이트 2 를 통과시키지 않는다 (측정 불가는 "측정 불가"로 채운다).
2. 임계값은 측정 **전에** 적는다. 측정 후에 맞추면 검증이 아니다.
3. 측정 불가 전제는 리스크로 미결 표에 올린다.
4. 측정 방법 칸에는 실행 가능한 명령이나 조회 절차만 쓴다.

**실행 환경 칸**: 같은 명령이 실행 위치에 따라 다른 답을 낸다(예: 리눅스 VM 의 git 과 Windows git 이
개행 설정 때문에 같은 저장소에서 다른 상태를 보고). 환경이 바뀌면 그 전제는 재측정 대상이다.

## 작업 필드

| 필드 | 값 | 규칙 |
|---|---|---|
| 쓰기 범위 | 파일 경로 또는 glob (`src/a/**`) | 병렬 판정의 입력. 모르면 병렬 판정 불가 |
| 공유 자원 | 이름 목록 | git 에 안 보이는 충돌 원천. 장비, 라이선스 프로그램, 빌드 출력 폴더, 같은 대장 파일 |
| 예상(분) | 정수 | 하한(기본 30분) 미만이면 직렬 권장 |
| after | 작업 이름 목록 (선택) | 이 작업이 산출물을 쓰는 선행 작업. 같은 단계에 놓이지 않는다 |
| tier | T0 / T1 / T2 | 아래 |
| oracle | `<테스트 경로>` / `none` | 아래 |

### tier - 되돌릴 수 있는가 + 기계적 합격 판정이 있는가. 난이도가 아니다

| tier | 조건 | 사람 |
|---|---|---|
| T0 | 읽기 전용, 산출물은 보고서 | 착수 승인 불필요 |
| T1 | 작업 폴더·출력에만 씀, 원본 불변 | 결과를 읽을 때 |
| T2 | 원본 수정 / 커밋 | 착수 게이트 유지 |

반례: 운영 설정 한 줄 수정은 쉽지만 되돌리기 어려운 곳으로 바로 나가므로 T2. 큰 문서를 적대적으로 읽는 일은 복잡하지만 읽기 전용이라 T0.

### oracle - 오라클을 건드릴 수 있으면 오라클이 아니다

- `oracle: <경로>` - 작업 내부 자율 허용. 그 경로는 구현자 쓰기 금지
- `oracle: none` - 자율 금지. 변경 단위마다 사람이 본다
- 오라클 파일이 수정된 흔적이 있으면 초록이어도 그 실행은 무효

## 병렬 실행 조건 (check_parallel.py 가 판정)

1. 작업끼리 쓰기 범위가 겹치지 않는다
2. 여러 작업이 같이 쓰는 계약(인터페이스·스키마)이 동결됐다
3. 공유 자원이 겹치지 않는다
4. 작업이 하한보다 크다

병렬로 돌린 작업은 **합친 뒤 통합 검증 1회가 필수**다. 각자 통과는 합쳐서 통과가 아니다.
병렬 작업은 대장 파일(미결·우려 목록 등)에 직접 쓰지 않는다. 결과 보고에 등록 제안만 적는다.

## 판정 어휘

판정 칸에는 다음만 쓴다: **통과 / 미달 / 조건부(조건 열거) / 측정 불가 / 미검증**.
"대체로 통과", "문제없어 보임", "추후 확인"은 판정이 아니다.
증거 없이 통과라고 쓰는 것이 실패다. 모르는 것은 실패가 아니다 - "미검증"이라고 쓴다.

## 결정을 적을 때

결정마다 "어떤 사실이 바뀌면 다시 볼 것인가"를 적는다. 쓸 수 없으면 결정이 아니라 임시 선택이므로 그렇게 표기한다.
