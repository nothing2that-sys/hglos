# HGLOS 프로젝트 대시보드

공통 진입을 먼저 읽는다: 원본 `../../ENTRY.md`, 설치본 `ENTRY.md`. 필수 공통 규칙을 생략하지 않는다.

먼저 `HOST.md`를 읽는다(설치 번들은 스킬 루트의 `HOST.md`, plugin 배치에서는 `../../HOST.md`, 원본: `plugin/hglos/HOST.md`). 대시보드는 설계·구현·검증의 네 번째 단계가 아닌 지원 기능이다.

## 입력 선택

저장소와 사용할 계획서·우려 대장을 확인한다. 기존 대시보드/진도표가 있으면 먼저 읽고 같은 목적의 파일을 중복 생성하지 않는다.
사용자가 지정하지 않았으면 `doc/*Slice*Plan*.md`와 `doc/CONCERNS.md`를 후보로 제시하고 실제 내용을 읽어 선택한다.
파일명이나 mtime으로 정본·승인·완료를 추정하지 않는다. 테스트 fixture나 레거시 STATE.json은 입력으로 쓰지 않는다.

## 생성

```text
python <이 스킬>/scripts/dashboard.py --repo <저장소> --plan doc/Slice_Plan_A.md --concerns doc/CONCERNS.md --output validation/dashboard.html --diagram-dir validation/diagrams
```

`--plan`은 반복 가능하다. `--concerns`와 `--diagram-dir`는 선택이고 출력 확장자는 `.html` 또는 `.md`다.
화면을 보는 요청은 기본으로 HTML을 생성한다. Markdown은 근거·보관용이며 Mermaid 표시 여부는 뷰어에 따른다.
원본 링크와 Markdown의 "원본:"은 출력 파일 위치 기준 상대 경로이고 생성 시각은 실행 환경 시간대로 표시한다.
상단에는 문서 작업의 상태별 건수와 바로 아래 상태별 작업 목록을, 각 계획서에는 현재/다음 행동과 큰 작업 의존도를 먼저 배치한다.
노드에서 작업 카드로 이동한 뒤 Enter/Space로 상세를 펼친다. fragment 이동만으로 자동 펼침을 주장하지 않는다.
숫자는 계획서별 작업 정의 행의 신고 집계다. 같은 작업명이 다른 계획서에 있어도 합치지 않는다.
일정·소요시간·완료율·실제 차단 원인이나 작업↔세션 담당자를 입력 없이 만들어내지 않는다.
세션 협업을 사용 중이면 `coordination.py --repo ROOT snapshot`으로 수집한
`--sessions .hglos/runtime/sessions.json`을 명시적으로 추가할 수 있다. 이 경우 `--plan` 없이 세션 현황만
생성할 수도 있다. 수집 시각·스냅샷 해시·대기 이유·선점·미종료 호출을 표시하며 DB를 직접 열거나 갱신하지 않는다.
세션 이름을 펼치면 소유 관계 SVG, 전체 선점 목록, 마지막 신고 사유, 미종료 호출의 도구·ID·시작 시각을 볼 수 있다.
파일·자원별 소유 목록과 요약 수치는 같은 스냅샷 모델에서 계산한다. 중복 ID·소유자 불일치·잘못된 호출 입력은 거절한다.
`--diagram-dir`는 계획서별 단계 흐름·작업 의존도의 SVG와 Mermaid 원본을 내보낸다.
출력 파일이 있으면 먼저 읽어 생성 보고서인지 확인하고 갱신 요청이 있을 때만 `--overwrite`를 붙인다.
다른 문서·계획서를 출력 경로로 지정하지 않는다. 등록할 source는 저장소 안의 UTF-8 Markdown이다.

먼저 [시각화 패턴과 상태 입력 계약](references/visual-patterns.md)을 읽는다. 공개 스킬에서 참고한 방식과 출처도 그 문서에 있다.
상단에 프로젝트명·생성 시각·입력 문서 수를 표시한다. 계획서마다 계획→구현→검증 흐름,
현재 위치·다음 작업·결정 필요·확인 사실 카드, 작업 상태 보드, after 의존도, 종결 조건 근거표를 만든다.
Current State, 승인 관련 원문, 종결 조건, 미결, 작업 분할은 접어 볼 수 있는 원문으로 함께 남긴다.
원본 링크·SHA-256과 긴 근거는 상세 영역으로 모은다. 단계는 설계→구현→검증 세 개를 유지한다.
상태는 Current State 안의 `단계 현황`·`작업 현황` 표에 명시된 값만 읽는다. 승인 후 작업 분할은 상태 갱신 때문에 바꾸지 않는다.
누락·중복·미인식 상태는 미검증으로 남기고, 선행 누락·순환·24개 초과 도식은 경고와 원문으로 돌린다.
우려 대장의 상태 집계는 문서 표기의 집계이며 실제 위험 해소 판정이 아니다.

## 보고

생성 파일 링크, 읽은 원본과 SHA-256, 누락된 절, 다음 작업의 원문을 알린다.
HTML은 로컬 브라우저에서 레이아웃을 확인한다. 원본에 적힌 승인·통과는 재검증된 승인이 아니며
실시간 장비·세션 상태 또는 자동 진행률로 표현하지 않는다. 문서가 바뀌면 명시적으로 다시 생성한다.
세션 스냅샷도 `snapshot`과 dashboard 재생성을 거쳐야 갱신된다. 세션 종료/working/해시 일치를
프로젝트 완료/PASS/승인으로 해석하지 않는다.
세션 상태는 신고 기록이고 `reason`은 마지막 신고 사유다. 과거 충돌 문자열에서 현재 차단자·해제 허가를 만들지 않는다.
JavaScript 없이 native details/summary로 펼친다. 파일·자원 목록은 동일 이름별 소유 기록이며
하위 폴더/전체 작업 영역 겹침을 판정하거나 병렬 작업을 허용하지 않는다.
HTML 확인 시 펼친 카드, Tab/Enter/Space, 긴 이름, 좁은 화면의 스크롤·잘림과 SVG/텍스트 일치를 확인한다.
필요한 카드를 펼친 뒤 인쇄한다. 실제 브라우저 확인과 구조 검사 결과를 구분해 보고한다.
원본 계획서·우려 대장은 수정하지 않는다. 생성물을 새로운 상태 정본으로 쓰지 않는다.
