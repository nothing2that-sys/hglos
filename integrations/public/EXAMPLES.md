# 복사해서 쓰는 예시

먼저 [완성된 가상 대시보드](dashboard/index.html)를 내려받아 브라우저에서 열어보세요.
[미리보기](dashboard/preview.png)에서 진행·차단·완료·미검증 표시와 설계→구현→검증 흐름을 볼 수 있습니다.
이 화면의 상태는 학습용 가상 데이터이며 실제 시험 결과가 아닙니다.

아래는 가상의 C# 설정 저장 오류입니다. 실제 프로젝트·증상·계획서 경로로 바꾸세요.
Codex는 `$hglos-...`, Claude는 `/hglos-...`, plugin은 `/hglos:hglos-...`를 사용합니다.

## 설계: 첫 대화

```text
$hglos-design
현재 C# 프로젝트에서 빈 목록을 저장한 뒤 읽으면 null이 되는 문제를 고칠 계획을 세워줘.
실제 저장·로드 호출 경로부터 확인해줘. public API와 기존 JSON 포맷은 보존해야 해.
UI 재설계와 무관한 리팩터링은 제외해줘.
빈 목록·기존 데이터·잘못된 입력의 검증 기준을 먼저 정해줘.
범위와 계획 승인에서 멈추고 doc/Slice_Plan_Settings.md에 기록해줘.
```

질문에 답하고 내용을 확인한 뒤 범위·계획을 각각 승인합니다. 저장소의 승인·커밋 규칙을 따르세요.
[학습용 계획서](Slice_Plan_Settings.md)는 승인란이 비어 있어 구현에 사용할 수 없습니다.

## 구현: 새 대화

```text
$hglos-implement
실제로 승인된 doc/Slice_Plan_Settings.md에 따라 구현해줘.
기존 사용자 변경을 보존하고 원인을 재현하는 테스트를 추가해줘.
허용된 소스만 변경하고 빌드·테스트 결과와 제한을 보고서에 기록해줘.
이 프로젝트에서는 MAIN만 코드를 수정해. 커밋하지 마.
```

기대 결과는 변경 파일·재현 결과·원인·테스트·제한이 담긴 보고서입니다.

## 종결 검증: 독립된 새 대화

```text
$hglos-verify
모드 B로 doc/Slice_Plan_Settings.md의 종결 조건을 대조해줘.
구현자 결론을 전제하지 말고 실제 소스와 실행 근거를 확인해줘.
소스 수정·커밋 금지. 산출물을 쓰는 테스트는 MAIN 실행 로그로 확인한 범위를 구분해줘.
조건별 판정·파일 위치·근거·미검증을 기록해줘.
```

기대 결과는 검증자 정보·revision·변경 범위·조건별 판정·근거·위험입니다.
미달이면 보완하고 다시 검증합니다. 최종 종결은 사람이 승인합니다.

## 변경분 검토만 하기: 계획서 없이 모드 A

```text
$hglos-verify 모드 A로 현재 Git 변경분을 검토해줘.
호환성·예외 경로·공유 상태를 우선하고 근거 위치와 재현 조건을 기록해줘.
소스 수정·커밋 금지. 독립 검증 수단이 없으면 새 세션 전달문을 만들어줘.
```

## 현황만 보기

```text
$hglos-dashboard doc/Slice_Plan_Settings.md로 validation/settings-dashboard.html을 만들어줘.
미검증은 미검증으로 표시하고 다음 작업과 근거 위치를 보여줘.
```

실행 가능한 대시보드 명령은 [사용 설명서](../docs/USER_GUIDE.md)에 있습니다.
